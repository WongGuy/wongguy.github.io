# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A lightweight website designed to aggregate mechanical reference materials into a single unified source. Designed to have simple mechanical calculators, tables, charts, etc.

## Structure

Static site, no build step, no framework, no dependencies — plain HTML/CSS/JS loaded directly by the browser.

- `index.html` — a bare redirect (meta refresh) to `screw-selector.html`, kept only so GitHub Pages has a root document at `/`. Don't put real markup here.
- `screw-selector.html`, `nut-selector.html`, `washer-selector.html`, `nasa-tightening-torque.html`, `bolt-size-estimation.html`, `torque-tension-diagram.html`, `pem-nut-torque.html`, `pem-standoff-torque.html` — one page per reference tool. Each has its own `<section class="chart-card">` and an empty `<div class="site-nav"></div>` that `tab-nav.js` fills with the shared two-level nav.
- `sheet-metal.html`, `pem-selection.html` — empty "WIP" placeholder pages: the shared header, nav and footer plus a titled `chart-card`, with no `tools/` folder yet. They're already in `site-nav-data.js`, so building one out means filling in its card, not touching the nav. Copy one of these when stubbing a new page.
- `style.css` — all styling. Colors as CSS custom properties on `:root`, plus a `:root[data-theme="dark"]` block overriding the same properties for dark mode.
- `theme.js` — shared, page-agnostic dark-mode toggle. Reads/writes `localStorage` and sets `data-theme` on `<html>`; has no knowledge of any page's actual colors. Include it in `<head>`, before the stylesheet link, so the theme is applied before first paint. Any page also needs a `#theme-toggle` checkbox (see the `.theme-switch` markup in `screw-selector.html`) for the toggle to attach to.
- `site-nav-data.js` — the site's navigation structure: a list of top-level categories, each with the pages it contains. This is the only file to edit when adding, renaming, or recategorizing a page in the nav.
- `tab-nav.js` — shared, page-agnostic navigation renderer. Builds both nav bars into each page's `<div class="site-nav"></div>` from `site-nav-data.js`. The upper bar (`.category-nav`) holds the top-level categories as buttons — clicking one only swaps which tabs the lower bar shows, it never navigates. The lower bar (`.tab-nav`) holds that category's pages as links, and is the only part that navigates. On load the selected category is whichever one contains the current page. Pages just need the empty `<div class="site-nav"></div>` plus the `site-nav-data.js` and `tab-nav.js` includes — no hardcoded tab markup.
- `footer.js` — shared, page-agnostic footer content. Populates every page's `<footer>` on load with the common links (source data tables, attribution). Each page just needs an empty `<footer></footer>` and the script include.
- `flowchart.js` — shared, page-agnostic decision-tree flowchart renderer. `renderFlowchart(container, data, options)` takes a plain JSON tree (see the doc comment at the top of the file for the Node/Edge shape) and builds it as real DOM boxes with CSS-drawn connector lines, so it reflows and wraps on resize instead of breaking a fixed-width layout. Each page that shows a flowchart gets its own `tools/<tool>/<tool>-flowchart-data.js` holding just the JSON tree (plus any page-specific wiring, e.g. a detail toggle) and an empty `<div id="flowchart" class="flowchart"></div>` — see `tools/nut/nut-flowchart-data.js` (uses `options.activeTags` to toggle fine-pitch variants) and `tools/washer/washer-flowchart-data.js` (no toggle) for two different shapes of tree reusing the same renderer.
- `plot.js` — shared, page-agnostic line-plot renderer, the plotting counterpart to `flowchart.js`. `renderLinePlot(container, options)` takes a list of series (each a label, a color, and `{x, y}` points) and draws real SVG axes, gridlines, lines, markers, a legend, and a hover tooltip, re-measuring the container and redrawing on resize so the plot reflows instead of scaling. It knows nothing about what's plotted — axis titles, tick formatting, and tooltip text all come in as options. Passing the optional `legendItems` (each with an `onToggle`) turns the legend into the plot's series control: the rows are drawn as given rather than derived from what's on the plot, so a series switched off keeps a row to switch back on, and the legend survives an empty plot — whose `emptyMessage` box takes the height of the last plot drawn at that width, so emptying the plot doesn't shift the page. A legend item with its own `items` is a group — its checkbox heads a line, its child items follow — and once any item is a group the legend lays out as a two-column table of heads and items; what a group toggle does to its children is the page's call. Adding `legendSlots: n` fixes that table's layout so it never changes size: the legend takes the plot's width, each group's items fill n equal cells (padded with empty ones, ellipsized when too long), so a page that passes every group every time — with `disabled` on the ones that have nothing to offer — gets a legend that stays put. A `null` among a group's items is an empty cell, so an item can keep its column on every line and be blank where a group lacks it (the PEM standoff page's materials). Passing `xCategories` makes the x axis categorical (category i at x = i, gridlines on the band edges, labels stacked per line or rotated 45° when they don't fit), and a series with `line: false` draws unconnected markers — together that's a dot plot, as on the PEM nut torque page. A series can also set a marker `shape` (circle, square, triangle, diamond, triangle-down) and `hollow`, ten looks in all, and a legend item with the same `shape` / `hollow` shows that marker as its swatch. `legendActions` (each a `key`, `label` and `onClick`) adds a row of buttons under the legend. A series with `bar: true` (and an optional `barWidth` in x units) draws its points as bars from zero instead, hit-tested over the whole bar for the tooltip — with `xCategories` and dodging, a grouped bar chart, as on the PEM standoff torque page. Two helpers are exported beside it for pages that show the same data without the plot: `renderPlotLegend(container, options)` draws just the legend (same `legendItems` / `legendSlots`), and `createPlotMarker({ shape, hollow, color })` returns one marker as an inline SVG. Series colors are the `--series-N` custom properties in `style.css`, so lines follow the theme. Every drawn plot also gets a "Copy image" / "Save PNG" row under its legend (Copy only where the browser supports image clipboard writes). The image is built as a standalone SVG — the plot cloned with each element's computed style inlined, the optional `title` option printed above it (the page's own heading isn't part of the plot, so each page passes its title text), and the legend redrawn as SVG with only what's on the plot (items that are off, disabled, noted, or set `exportable: false`, like the torque-tension page's α checkbox, are left out) — always in the light theme, then rasterized at 2x to PNG.
- `tools/<tool>/` — each reference tool's own data file and rendering logic (e.g. `tools/nasa-torque/nasa-torque-data.js` + `tools/nasa-torque/nasa-torque-app.js`, `tools/screw/screw-data.js` + `tools/screw/screw-app.js`). The tool's page itself stays at the repo root — only the per-tool JS lives in subfolders — so GitHub Pages URLs don't move. Shared, page-agnostic files (`theme.js`, `tab-nav.js`, `footer.js`, `flowchart.js`, `plot.js`, `site-nav-data.js`, `style.css`) stay at root since every page includes them.
  - `tools/nasa-torque/nasa-torque-data.js` — reference data for the NASA tightening torque plot: `torqueMaterials` (the five materials, ordered by ultimate shear strength) and `torqueData` (one entry per fastener size, each holding per-material rows of thread engagement, pullout load, assembly torque, and 100 % torque). Generated — see `scripts/generate_nasa_torque_data.py`. Values here are plain metric numbers rather than display strings, because `nasa-torque-app.js` does arithmetic on them.
  - `tools/nasa-torque/nasa-torque-app.js` — DOM logic for `nasa-tightening-torque.html`: the size slider (same construction as the other selectors), the plot itself via `renderLinePlot`, and the assembly/100 % torque toggle. The materials are switched on and off from the plot's own legend — the page passes `legendItems` covering every material, not just the plotted ones — rather than from a separate checkbox block. Size, torque column, and material selection all persist in `localStorage`.
  - `tools/bolt/bolt-data.js` — ISO metric bolt reference data, shared by every page under Bolting Information rather than owned by one tool: `bolt-size-estimation.html` reads the loads, `torque-tension-diagram.html` reads the thread geometry and the per-class Rp0,2. `tools/bolt/` therefore holds data only — no app file — and anything specific to one page's method belongs in that page's own tool folder. Two halves. Generated (see `scripts/generate_bolt_data.py`): `boltSeries`, `boltLoadTypes`, `boltGrades` (each with a `properties` map of Rm / Sp on the nominal basis and Rp0,2 on the minimum basis, from ISO 898-1 Table 3 — class 8.8's Rp0,2,min splits by diameter like its Sp,nom), `boltGradeProperties`, `boltThreads` (one flat array of both coarse and fine threads, sorted by diameter then pitch, each tagged with its `series`, carrying the thread geometry — `pitch`, `d2` from ISO 724, `stressArea`, and `d0 = sqrt(4 As / pi)` — and proof and minimum ultimate tensile loads per property class) and `boltNotes`. Hand-maintained: `boltLoadCases` and `boltTighteningMethods`, which aren't ISO 898-1 data but the bolt size estimation method's own step counts and load condition schematics. Values are plain numbers because the apps compare, step through, and do arithmetic on them.
  - `tools/bolt-strength/bolt-strength-app.js` — DOM logic for `bolt-size-estimation.html`: the force-per-bolt input, the load condition and tightening method pickers, the load table, and the property class column toggles. The table bolds the smallest thread that carries the entered force in each class, steps down by the load condition's plus the tightening method's step count to highlight the estimate, and trims the rows to one either side of that band. Stepping walks only the rows a class is tabulated at, so classes that stop early (9.8 above M16) step through their own sizes; a class that can't see the estimate through is marked on its column header: if nothing in it carries the load nothing in the column is marked either, but if a bare minimum exists and only the step-down runs off the bottom, that yellow minimum cell stays marked and just the green recommendation is dropped. Force, load condition, tightening method, and column selection all persist in `localStorage`. Which load type and thread series are shown come from their lists in the data file, so adding a fine-thread or tensile-load toggle is wiring a control to those sets rather than changing the table build.
  - `tools/torque-tension/torque-tension-data.js` — the assumptions behind the torque-tension diagram, and nothing else: the friction range swept to draw the curve, the yield utilization ν, and the head bearing diameter as a multiple of d. None of it comes from a standard — the standards data the page uses is all in `tools/bolt/bolt-data.js` — so it's kept here where it can be read and changed without touching the plot code. The app renders the page's assumptions list from these values too, so the numbers quoted on the page can't drift from the numbers plotted.
  - `tools/torque-tension/torque-tension-app.js` — DOM logic for `torque-tension-diagram.html`: the size slider (same construction as the other selectors), the thread parameter readout pinned under it, and the plot via `renderLinePlot`. Draws one curve per property class that ISO 898-1 gives an Rp0,2 for (8.8 and up), each a parametric sweep of the friction coefficient through the two formulas printed at the top of the page — preload on Y, tightening torque on X, so the arc lands in the first quadrant. Classes are switched from the plot's own legend, as on the NASA torque page. Coarse pitches only, and like the estimation table it blocks the ISO 262 second-choice diameters (M3.5, M14, M18, M22, …) from the slider — `SECOND_CHOICE_DIAMETERS` in the app — so it steps through the R10 preferred series. Size and class selection persist in `localStorage`.
  - `tools/pem-nut-torque/pem-nut-torque-data.js` — `pemNutSeries`, one entry per PEM table (S, CLS, SP, CLA, SH / HNL / H, RT, SMP, WN / WNS, KF2), each with its nut factor K, its own footnotes, its mating screw `materials` in the order the table prints them (CLA's column set differs from the rest, so this is per table), and its `parts` in sheet order, each carrying the thread size read from its part number, min. axial strength, screw strength to develop it, and one torque per material. Generated — see `scripts/generate_pem_nut_torque_data.py`. Unlike the NASA and bolt data, values are strings exactly as printed ("0.40"), because the app only plots and prints them and a printed trailing zero is significant; the generator gets the decimal places from each cell's number format.
  - `tools/pem-nut-torque/pem-nut-torque-app.js` — DOM logic for `pem-nut-torque.html`: the size slider (every size any PEM table lists), a Chart | Table toggle (same skin as the NASA page's torque toggle; the table view lists the same shown parts grouped by series, with strengths and one torque column per material, plain — no markers or colors in the cells or in its legend — with the legend drawn under it via `renderPlotLegend` so the selection works in both views; both legends end in "Check all series" / "Uncheck all series" buttons that set every table's head, grayed-out ones included), and a dot plot via `renderLinePlot` with `xCategories` — one series per part number at the selected size across all tables, markers dodged among the shown parts within each material's band so equal torques don't hide each other. The categories are the tables' material lists merged in print order, trimmed to the tables with a part shown (CLA's Aluminum column appears only while a CLA part is) and to the screw grades ticked in the "Screw Grades" group under the plot — one checkbox per merged material, with a "Show common" button ticking just A2-70, 8.8, 10.9 and 12.9 (the four drawn bold), built like the bolt size estimator's property class picker with its `est-grade-*` classes. The grade filter cuts the table view's torque columns too. With exactly one grade ticked (the checkbox count, not what survives trimming) the chart becomes a bar chart instead: x axis "Series", one band per table with a torque at that grade, the shown parts as bars side by side in their legend colors, the legend's table markers dropped (the axis now says the table), and the grade added to the title. One grade ticked also brings up a second plot under the grade list (`#size-plot-group`, in either view of the first): the same torque axis against "Thread Size", every size at once (the slider doesn't move it). A part number exists at only one size, so this plot works in part families — the part number with its size replaced by `M*` ("S-M*-0ZI", "S-RTM*-0ZI") — one dot series per family in its table's marker and its color on that table's legend line, dodged among the families present in each size band. Its legend is built like the main one (a line per table headed by its checkbox, then its families; the same head rules, "Check all series" / "Uncheck all series", and fixed `legendSlots` cells — at most four per row so the family names fit uncut; S and CLS, with seven families each, wrap onto a second row, and those seven colors on one line are why `--series-6` / `--series-7` exist), with a table or family that has no torque at the grade locked. Its selection is kept apart from the main legend's. A two-knob slider at the top of its group, above its title (two `.size-slider` inputs stacked in one grid cell — `.range-slider` in `style.css` — so each knob looks like the torque-tension page's μ_min slider, with the track solid between the knobs and the knobs staggered evenly about the track, upper raised and lower dropped by `--knob-stagger`, so the two stay distinct when they meet), sets the smallest and largest size it spans in both views (a knob dragged past the other pushes it along); a family or table with no torque in that span is grayed out in its legend. It has its own Chart | Table toggle; its table view is a row per shown family grouped by table, one torque column per size on the axis, with its legend under it. Tables and parts are both switched from the plot's own legend, grouped: one line per table, always — a table that doesn't list the size is grayed out with its head locked rather than dropped, and every line has `legendSlots` cells (the most parts any table lists at one size), so the legend doesn't change size as the slider moves. Each table has its own marker (shape, then filled or hollow, by table order) that all its parts plot with and its legend head shows; a part's color is its place on its table's line. Each line is headed by a table checkbox ("S") followed by its part checkboxes. Table and part state are kept separately, so unticking a table hides its parts and reticking it restores the ones that were on; ticking a part under an unticked table turns the table back on with just that part. View, size, hidden tables, hidden part numbers, hidden screw grades, and the thread size plot's view, size range, hidden tables and hidden part families persist in `localStorage` (hidden rather than shown, so a part or grade not seen before starts on; a first visit starts with one table on in each legend and every grade on). The K and footnote lines under the plot are rendered from the data for the tables drawn — or, when none is drawn at the size, the tables switched on, even if they don't list it — labeled by table when there's more than one.
  - `tools/pem-standoff-torque/pem-standoff-torque-data.js` — `pemStandoffSeries`, one entry per PEM standoff table (SO / SOS / SOA / BSO / BSOS / BSOA, SO4 / BSO4, DSOS / DSO), each with its footnotes, its `materials` (each a standoff material name and the PEM types made in it — `{ name: "Stainless Steel", types: ["SOS", "BSOS"] }`), its `testSheets`, and its `rows`, one per (thread code, standoff material): the max. recommended mating screw torque plus, per test sheet, installation / pushout / torque-out / pull-thru (or `null` where the source prints dashes). A row's `size` is the "M<d>" its thread code ends in, so 3.5M3 (3.5 mm body, M3 thread) is an M3 row. A table's `materials` are only the ones its rows use — that's what limits which materials the page lets a visitor tick (SO4 / BSO4 list Stainless Steel alone). Generated — see `scripts/generate_pem_standoff_torque_data.py`. Values are strings as printed, as in the nut data.
  - `tools/pem-standoff-torque/pem-standoff-torque-app.js` — DOM logic for `pem-standoff-torque.html`, built like the nut page with standoff materials in place of part numbers: the size slider (every size any table lists, 3.5M3 under M3), a Chart | Table toggle (same skin and behavior as the nut page's), and a grouped bar chart via `renderLinePlot` with `xCategories` and `bar: true`, one band per table and thread code at the size, table first so a table's 3.5M3 sits right of its M3 ("M3 / SO / BSO", "3.5M3 / SO / BSO", "M3 / SO4 / BSO4", …), trimmed to the tables with a material shown. One series per (table, material), colored by material, bars side by side within each band; the tooltip gives the PEM types, the torque, and the torque-out / pushout / pull-thru per test sheet. The table view lists the same rows in the same order — table, thread code, material (with its types and max. torque), then a line per test sheet with installation / pushout / torque-out / pull-thru — plain, with the legend under it (no color swatches) via `renderPlotLegend`. The legend has one line per table and one cell per material (Steel, Stainless, Aluminum — the same column, and color, on every line), but like the nut page's parts a line shows only the materials its table offers at the size: the others' cells are left empty (a `null` legend item — SO4 / BSO4 show Stainless alone, in the Stainless column), and a table that doesn't list the size is locked with no materials. Head / material state, "Check all series" / "Uncheck all series", and the notes follow the nut page's rules. View, size, hidden tables and hidden materials (per table, `"SO:Aluminum"`) persist in `localStorage`; a first visit starts with everything on.
  - `tools/screw/screw-data.js` — reference data tables for the screw selector (currently `screwData`, the ISO metric thread values, plus `screwFields` describing how to label/order them for display). This is the file to edit when adding or correcting screw reference values.
  - `tools/screw/screw-app.js` — DOM logic that reads `screw-data.js` and renders the screw selector's interactive controls (slider + spec panel). Wrapped in an IIFE, queries elements by ID, no globals besides what `screw-data.js` exposes.
- `assets/images/<tool>/` — static images for that tool's page (e.g. `assets/images/screw/thread-diagram.svg`). `nut/` and `washer/` exist as empty placeholders until those selectors have diagrams.
- `assets/standards/NASA/Torque/` — source-of-truth NASA torque data: `NASA_TM-2017-219475_Metric_Torque_Tables.xlsx` (one worksheet per material/size pair, transcribed from the report's metric tables) alongside the report PDFs. `scripts/generate_nasa_torque_data.py` rebuilds `tools/nasa-torque/nasa-torque-data.js` from the workbook, converting the US customary source values to metric on the way (in -> mm, lb -> N, lb-in -> N*m); it reads the xlsx with the standard library only, so the generators stay dependency-free.
- `assets/standards/ISO/screw/ISO Standards - ISO 898-1.xlsx` and `ISO Standards - ISO 724.xlsx` — the two source-of-truth workbooks behind `tools/bolt/bolt-data.js`. ISO 898-1:2013 carries Table 3 (mechanical properties per property class) plus one worksheet per (load type, thread series) pair (Tables 4-7 — ultimate tensile and proof loads, coarse and fine pitch); ISO 724:2023 carries Table 1 (basic dimensions) on a single worksheet, and supplies the pitch diameter d2, which ISO 898-1 doesn't tabulate and which can't be recovered from the stress area. `scripts/generate_bolt_data.py` rebuilds the generated blocks from both; like the NASA generator it reads the xlsx files with the standard library only. The values are already metric, so nothing is converted. The generator cross-checks the two workbooks against each other — ISO 724's (d2 + d3) / 2 must reproduce the d0 recovered from ISO 898-1's As — and stops if they disagree by more than the rounding of As.
- `assets/standards/PEM/Penn Engineering - Nut Torques.xlsx` — source-of-truth PEM nut torque tables: an Index sheet plus one worksheet per PEM table (part number, min. axial strength, screw strength, and the mating screw torque per material). `scripts/generate_pem_nut_torque_data.py` rebuilds `tools/pem-nut-torque/pem-nut-torque-data.js` from it with the standard library only, cross-checking every table against its Index row (title, row count, K, material columns) and stopping on any mismatch. A new worksheet must be added to the generator's `SERIES` map (its key and button label) before it will generate.
- `assets/standards/PEM/Penn Engineering - Standoff Torques.xlsx` — source-of-truth PEM standoff torque tables, transcribed from the text layer of `Penn Standoff Datasheet.pdf` (PDF page 7, bulletin pages SO-12 / SO-13, metric tables only): an Index sheet plus one worksheet per table with a mating screw torque (SO / SOS / SOA / BSO / BSOS / BSOA, SO4 / BSO4, DSOS / DSO). Each sheet has a row per (thread code, standoff material) — torque, then a four-column block (installation, pushout, torque-out, pull-thru) per test sheet material. The SO4 and DSOS / DSO tables print no material column; the sheets fill it from the bulletin's material specifications (page SO-8) and say so in their notes. The TSO / TSO4 tables (keyed by "C" dimension) and SOSG / SOAG (no torque column) aren't transcribed. `scripts/generate_pem_standoff_torque_data.py` rebuilds `tools/pem-standoff-torque/pem-standoff-torque-data.js` from it with the standard library only (inline or shared strings, so an Excel save doesn't break it), cross-checking every table against its Index row (title, row count, standoff materials with their types, test sheets) and stopping on any mismatch. A new worksheet must be added to the generator's `SERIES` map (its key and legend label) before it will generate.
- `assets/standards/ISO/<tool>/` — source-of-truth ISO standard CSVs for that tool (e.g. `assets/standards/ISO/screw/ISO Standards - ISO 262.csv`), checked in alongside a generator script (see `scripts/generate_screw_data.py`) that rebuilds the tool's `tools/<tool>/<tool>-data.js` from them. `nut/` and `washer/` exist as empty placeholders until those standards are sourced.

Each reference tool follows the same pattern: a data file (e.g. `tools/screw/screw-data.js`) describing the values, plus rendering logic (e.g. `tools/screw/screw-app.js`) that builds the table/panel from it. When adding a new reference tool, give it its own root-level `<tool>-selector.html`, a `tools/<tool>/` folder holding `<tool>-data.js` and `<tool>-app.js`, `assets/images/<tool>/`, and `assets/standards/ISO/<tool>/`, following this same data/render split rather than hardcoding values into HTML. Add the page to `site-nav-data.js` so it shows up in the nav.

When adding a new page, give it its own stylesheet (or its own `:root` / `:root[data-theme="dark"]` blocks) so it can define a completely independent light/dark palette — `theme.js` is shared and reusable as-is, but colors are never shared, they're per-page CSS custom properties.

## Working in this repo

- Assume this project is hosted on github pages, with the site being deployed from main. Make sure that the site can always be easily ported to standalone if needed.
- Avoid fillets on page elements when possible in favor of sharp rectangular elements.
